# 04 接口契约

> 版本：v0.1（2026-11-14）。每次修改接口把版本号加一，并在文末“变更记录”写一行。
> 接口是全组的“合同”。边界内怎么实现由负责人决定；**改边界（方法签名、行为约定、URL、JSON 字段）必须全组同意**，并同时修改：本文、对应的 `interfaces.py` 文档字符串、契约测试。

## 1. 模块之间：Python 接口

完整约定以代码中的文档字符串为准，下表是索引。

### 1.1 Repository（C）· `campus_eats/model/repository.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `initialize(campuses, venues, dishes, reviews=())` | None | 建表；没有数据时写入初始数据；可重复调用（幂等） |
| `list_campuses()` / `get_campus(id)` | list / Campus \| None | 按初始化顺序；不存在返回 None |
| `list_venues(campus_id=None)` | list[Venue] | 按初始化顺序 |
| `get_venue(id)` / `save_venue(venue)` | Venue \| None / None | 按 id 覆盖 |
| `list_dishes(venue_id=None)` | list[Dish] | 按初始化顺序 |
| `get_dish(id)` / `save_dish(dish)` | Dish \| None / None | 读回对象必须与存入对象完全相等（tuple / 枚举要还原） |
| `add_review(dish_id, rating, comment, author, created_at)` | Review | review_id 从 1 自增 |
| `list_reviews(dish_id=None, limit=None)` | list[Review] | created_at 降序，同时间按 review_id 降序 |
| `get_review(id)` / `delete_review(id)` | Review \| None / None | 删除不存在不报错 |
| `save_decision(decision)` / `list_decisions(since_ms=None, limit=None)` | — / list[Decision] | 最新在前；since 含 |
| `save_vote_room(room)` / `get_vote_room(code)` | — / VoteRoom \| None | 按 code 覆盖 |
| `list_vote_rooms(limit=50)` | list[VoteRoom] | 创建时间降序 |
| `save_ballot(ballot)` / `list_ballots(room_code)` | — / list[VoteBallot] | 按 (room_code, voter_token) 覆盖；时间升序 |

### 1.2 CatalogService（C）· `campus_eats/catalog/interfaces.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `list_campuses()` | list[Campus] | |
| `list_venues(campus_id=None, kinds=None, meal_period=None)` | list[Venue] | 只返回 available；时段表示“当前营业”；未知校区 → INVALID_FILTER |

### 1.3 ReviewService（E）· `campus_eats/review/interfaces.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `add_review(dish_id, rating, comment, author)` | Review | 评分 1–5 整数；昵称 1–20 字；评论 ≤200 字；同日同人同菜 → RATE_LIMITED |
| `list_reviews(dish_id, limit=20)` | list[Review] | 最新在前；limit 1–100；菜品不存在 → NOT_FOUND |
| `list_recent(limit=20)` | list[Review] | 全站最新，后台用 |
| `summary(dish_id)` | RatingSummary | 平均分 1 位小数；histogram 1–5 五个键都有 |
| `delete_review(review_id, operator)` | Review | 操作人必填；返回被删记录；不存在 → NOT_FOUND |

### 1.4 DecisionService / VoteService（B）· `campus_eats/decision/interfaces.py`

| 方法 | 返回 | 要点 |
|---|---|---|
| `candidates(filters)` | list[DishOption] | 按 03 §3 筛选；全部“最近吃过”时返回全部候选；完全无候选 → NO_CANDIDATE |
| `decide(filters, mode=WHEEL)` | DecisionResult | 加权随机；写历史；最多 2 个备选；理由可读 |
| `history(limit=20)` | list[HistoryEntry] | 最新在前；缺失菜品 / 地点的记录跳过 |
| `create_room(title, options, closes_in_ms, creator)` | VoteRoom | 2–8 选项；1 分钟–7 天；6 位唯一码 |
| `get_room(code)` | VoteResult | 自动处理截止；不存在 → NOT_FOUND |
| `cast_vote(code, voter_token, option_id)` | VoteResult | 一人一票，再投覆盖（改票）；已截止 → INVALID_STATE |
| `close_room(code, operator)` | VoteResult | 手动结束；重复结束 → INVALID_STATE |
| `list_rooms(limit=20)` | list[VoteRoom] | 最新在前 |

## 2. JSON 约定

- 字段名与 Python 实体一致（snake_case）。
- 枚举为字符串：`"CANTEEN"`、`"LUNCH"`、`"RICE"`、`"WHEEL"`、`"OPEN"`。
- 金额为整数分；时间为 epoch 毫秒。
- tuple 变成数组；`null` 表示无。
- `RatingSummary.histogram` 的整数键会变成字符串：`{"1":0,"2":0,"3":0,"4":1,"5":2}`。
- 实体 → JSON 统一用 `campus_eats.model.serialize.to_jsonable`。

**筛选条件**（POST `/api/decisions` 的 `filters`，字段都可省略）

```json
{
  "campus_id": "nh",
  "venue_ids": ["nh_main", "nh_floor3"],
  "kinds": ["CANTEEN", "WINDOW"],
  "meal_period": "LUNCH",
  "max_price_fen": 1500,
  "categories": ["RICE", "NOODLE"],
  "include_tags": ["招牌"],
  "exclude_tags": ["辣"],
  "exclude_dish_ids": ["nh_main_sour_noodle"],
  "exclude_recent": true,
  "recent_days": 7
}
```

**错误**

```json
HTTP 409
{"error": {"code": "NO_CANDIDATE", "message": "没有符合条件的菜，放宽一个筛选条件试试"}}
```

## 3. 前后端之间：HTTP 接口（A 实现于 `web/api.py`）

### 3.1 页面

| 路径 | 页面 |
|---|---|
| `GET /` | 抽签首页 `index.html` |
| `GET /vote/<code>` | 投票页 `vote.html`（code 由前端从 URL 读取） |
| `GET /admin` | 管理后台 `admin.html` |

### 3.2 公共数据

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/meta` | — | 校区列表、枚举值、动态标签、分类 |
| GET | `/api/campuses` | — | `Campus[]` |
| GET | `/api/venues` | `campus_id`、`kind` / `kinds`、`meal_period` | `Venue[]`（只含营业中） |
| GET | `/api/dishes` | `venue_id`、`category`、`q`、`include_unavailable` | `Dish[]` |
| GET | `/api/dishes/<id>` | — | `DishDetail` |
| GET | `/api/dishes/<id>/rating` | — | `RatingSummary` |

### 3.3 抽签与评价

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| POST | `/api/decisions` | `{"filters": {...}, "mode": "WHEEL"}` | **201** `DecisionResult` |
| GET | `/api/decisions?limit=20` | — | `HistoryEntry[]` |
| POST | `/api/reviews` | `{"dish_id","rating","comment","author"}` | **201** `Review` |
| GET | `/api/reviews?dish_id=&limit=` | — | `Review[]`（无 dish_id 时返回全站最新） |

### 3.5 管理后台

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/admin/summary` | `campus_id`、`since_ms`、`until_ms` | `StatsSummary` |
| GET | `/api/admin/popular` | `limit`、`campus_id` | `TopDish[]` |

| POST | `/api/admin/reviews/<review_id>/delete` | `{"operator": "管理员"}` | 被删除的 `Review` |

### 3.6 错误码与 HTTP 状态

| code | HTTP |
|---|---|

| NOT_FOUND | 404 |
| NO_CANDIDATE、INVALID_STATE | 409 |
| RATE_LIMITED | 429 |

## 4. 修改流程

1. 在群里提出：改什么、为什么、影响谁；
2. 相关负责人同意后，由提出人同时修改本文、`interfaces.py` 文档字符串、契约测试；
3. 跑 `pytest -k reference`，参考实现必须仍然全绿；
4. 提交说明里写清楚“接口变更”。
