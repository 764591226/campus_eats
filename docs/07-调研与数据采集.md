# 07 调研与数据采集

> 目的：让“今天吃什么”不是一份编出来的菜单。老师第一讲就强调小微项目要**解决具体问题**，而群里也一致认为：前后端本身不复杂，**真实的多校区调研**才是本组显得“认真”的地方。
> 本文同时是数据规范：调研结果按这里的字段整理成 CSV，用 `tools/import_survey.py` 导入 SQLite。

## 1. 原则

1. **真实、可追溯**：每条数据写清楚来源（`SURVEY` / `DEMO` / `TAKEOUT`）、调研日期、调研人。页面上必须能看出哪些是演示数据。
2. **合规**：只记录食堂 / 窗口公开张贴的菜单和价格；拍照前征得窗口同意；**不爬取**美团、饿了么等平台的页面、接口或评论，也不用脚本批量抓取。外卖只做手工录入的少量样例并标注“外卖样例”。
3. **隐私**：不收集姓名、学号、手机号、定位；问卷匿名，只保留汇总结果；照片里出现的人脸要打码或避开。
4. **不过度**：每个校区 2–3 个就餐点、每个点 3–8 道有代表性的菜；覆盖主食 / 面食 / 小吃 / 套餐 / 饮品即可，不做全量菜单。

## 2. 校区与分工（建议）

| 校区 | 建议负责人 | 覆盖目标 | 备注 |
|---|---|---|---|
| 南湖校区 | B（住附近、有电动车，群里主动认领） | 南湖食堂 + 1 个外卖样例 | 最容易跑，作为第一批数据 |
| 马房山校区 | C、D | 东院食堂、西院食堂 | 两人分头，拍菜单板 + 记价格 |

> 分工可根据实际住址 / 时间互换；**每个校区至少 2 人知道数据怎么来的**，避免答辩时只有一个人能解释。

## 3. 采什么（字段表）

`surveys/survey-template.csv` 是可直接填写的模板，一行 = 一道菜，同一窗口的菜重复填窗口字段（按 `venue_id` 去重）。

| 列 | 含义 | 示例 | 规则 |
|---|---|---|---|
| venue_id | 窗口 / 食堂稳定 ID | `nh_survey_1` | 英文 + 下划线，全组不重复 |
| campus_id | 校区 ID | `nh` | 只能是 `ms` / `nh`（新增校区先改 seed） |
| venue_name | 名称 | `南湖食堂一楼` | 与现场招牌一致 |
| venue_kind | 类型 | `CANTEEN` / `WINDOW` / `TAKEOUT` | 三选一 |
| location | 位置 | `南湖·一楼东侧` | 方便同学找到 |
| open_periods | 营业时段 | `BREAKFAST;LUNCH;DINNER` | 分号分隔，取值见下 |
| venue_tags | 窗口标签 | `大众菜;经济` | 分号或逗号分隔 |
| dish_id | 菜品稳定 ID | `nh_survey_tomato` | 英文 + 下划线，全组不重复 |
| dish_name | 菜名 | `番茄炒蛋盖饭` | 与菜单一致 |
| category | 分类 | `RICE` | `RICE` / `NOODLE` / `SNACK` / `SET` / `DRINK` / `OTHER` |
| price_fen | 价格（分） | `1200` | 整数，12 元 = 1200；不要写“12元” |
| dish_tags | 菜品标签 | `素;清淡` | 用于筛选，建议 1–3 个 |
| description | 一句话描述 | `家常味` | ≤120 字 |
| source | 来源 | `SURVEY` | 调研数据一定是 SURVEY |
| available | 是否在售 | `1` | `1/0`、`是/否`、`true/false` |

时段取值：`BREAKFAST`（早餐）、`LUNCH`（午餐）、`DINNER`（晚餐）、`LATE_NIGHT`（夜宵）。

### 标签建议词表（尽量复用，避免同义词）

口味：`辣`、`微辣`、`酸辣`、`清淡`、`甜`、`咸香`
食材：`肉`、`素`、`高蛋白`、`海鲜`
属性：`招牌`、`便宜`、`实惠`、`套餐`、`早餐`、`夜宵`、`热乎`、`解辣`
来源：`外卖`、`轻食`、`快餐`

## 4. 现场怎么记

1. **先拍窗口全景 + 菜单板**（征得同意），文件名：`校区_食堂_窗口_日期.jpg`。
2. 每个窗口选 3–8 道：至少 1 道招牌、1 道最便宜、1 道素食或清淡；价格以菜单板 / 收银小票为准。
3. 记营业时段：直接问窗口或看门口牌子；拿不准就填午餐 + 晚餐，并在备注里说明。
4. 记 1–2 句真实观察：排队时长、分量、口味。不要写“很好吃”这种空话，写“12 点排队约 8 分钟”“肉量偏少”。
5. 当天把数据填进 CSV，并在一行里写清日期（可放在 description 末尾或单独维护 `调研记录.md`）。
6. 回宿舍后核对：ID 不重复、价格是分、校区 ID 正确、`source=SURVEY`。

## 5. 导入与校验

```bash
# 1. 只校验，不写库
python tools/import_survey.py surveys/nanhu.csv --dry-run

# 2. 导入（默认 data/campus_eats.db）
python tools/import_survey.py surveys/nanhu.csv

# 3. 启动看效果
python run.py --real all --open
```

导入工具的规则：

- `venue_id` 相同 → 只建一个窗口；`dish_id` 相同 → 覆盖（幂等，可重复导入修正）。
- 校区 ID 不存在 → 拒绝并提示先补校区定义（校区定义在 `campus_eats/model/seed.py`，改动需全组同意）。
- 价格必须是 0–100000 的整数分；分类、时段、来源枚举必须合法。
- 导入不会删除已有数据；要重新来一遍就备份 / 删除数据库文件后重启。

## 6. 数据质量检查（E 负责）

- [ ] 每行都能追溯到一张照片或一次现场记录；
- [ ] `source=SURVEY`，没有把演示数据冒充调研数据；
- [ ] 同一窗口的 `venue_name` / `location` / 时段一致；
- [ ] 菜品 ID、窗口 ID 全局唯一；
- [ ] 价格在合理区间（0–1000 元），没有把“12 元”写成 `12`；
- [ ] 标签在上面的词表内（新词先在群里确认）；
- [ ] 页面筛选、抽签、评分都能看到新数据；
- [ ] 至少 2 个校区、每校区 2 个就餐点、每个就餐点 3 道菜（最低验收线）。

## 7. 学生偏好问卷（可选加分）

如果时间允许，可以做一份匿名问卷（问卷星 / 腾讯问卷），用来**调整标签和权重**，不是用来伪造评分：

1. 你每周在校内食堂吃几顿？
2. 选菜最看重什么（价格 / 口味 / 距离 / 排队 / 卫生）？
3. 能接受的午餐预算是多少？
4. 最常去的校区 / 食堂？
5. 最想吐槽的一道菜是什么？（开放题，不收集身份信息）

样本 ≥30 份即可，结果只做汇总（例如“60% 的同学午餐预算 ≤15 元”），写进报告，不作为推荐算法的唯一依据，更不能生成假的菜品评分。

## 8. 外卖样例怎么处理

- 只手工录入 2–3 个“外卖商家 / 套餐”作为选项来源，标注 `source=TAKEOUT`，页面显示“外卖样例”。
- 不接真实平台下单、不抓取评论、不展示真实店铺评分；演示时说明“外卖只是数据源之一，后续可换成团购 / 平台接口”。
- 如果老师问“为什么不直接接美团”，回答：接口授权、合规、稳定性与课程范围；我们把接口设计成可替换的数据源。
